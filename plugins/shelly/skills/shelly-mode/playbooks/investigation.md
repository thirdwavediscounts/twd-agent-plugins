### Investigation

An answer, not a code change: how does X work, why was Y built this way, are we sure, X or Y?

1. Classify: mechanism → `/shelly:how` (Explain); "are we sure" → `/shelly:how` (Critique); motivation or regression history → add `/shelly:why`; cross-system symptom with unknown cause → `/investigate` (posts findings + sub-issues to Linear).
2. Run it. Verify any load-bearing claim a delegate makes with one read-only query or file read before repeating it.
3. Reply in the `/how` shape (Overview / Key Concepts / How It Works / Where Things Live / Gotchas) or a recommendation with a tradeoffs table, with your real judgment.
4. An Act-on finding about shipped code: draft it as a Linear sub-issue in the reply (title, one-paragraph body, parent ticket); file on the user's go.
5. If the answer precedes a code change, hand back and re-route to Bug fix or Feature.
